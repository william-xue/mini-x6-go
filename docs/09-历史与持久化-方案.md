# 第 9 课 · 撤销/重做与存档（方案课）

> 状态：方案和最小演示已完成，等待内化。
> 这一课不追求把每种操作都写完；目标是能独立设计同类功能。

## 1. 这一课只回答两个问题

```text
撤销/重做：用户怎么在编辑历史上前进、后退？
存档：关掉页面后，怎么恢复当前模型？
```

它们不是同一个功能：

```text
历史   保存「怎么变过来的」
存档   保存「现在长什么样」
```

## 2. 撤销/重做的心智模型：时间轴

```text
移动 A       新增 B       删除 C
  C1    →      C2    →      C3
                             ↑
                           当前
```

撤销一次：把 `C3` 倒着执行，当前点往左走。

```text
C1 → C2 → C3
     ↑
   当前
```

重做一次：把 `C3` 正着执行，当前点往右走。

撤销后做新动作：旧的未来被丢掉。

```text
原来：C1 → C2 → C3
撤销：C1 → C2
新做：C1 → C2 → C4       // C3 不再能重做
```

代码用了「撤销栈 + 重做栈」，脑子里想成「时间轴 + 当前位置」即可，两者等价。

## 3. 什么算一次操作

```text
一次用户意图 = 一条历史记录
```

拖动实例时：

```text
pointerdown
  ↓
pointermove 触发几十次，Model 实时变化，但不记历史
  ↓
pointerup，只记「从哪 → 到哪」一条记录
```

复杂删除时：

```text
删除一个实例
+ 级联删除它连接的 3 条边
= 用户的一次删除意图
= 一条 transaction
```

Qt 叫 macro，X6 叫 batch，本课叫 transaction，含义相同。

## 4. 一条记录要保存什么

原则：

> 保存足够的信息，让操作能正着做，也能倒着做。

移动：

```json
{
  "type": "instance:move",
  "id": "instance-1",
  "from": { "x": 30, "y": 20 },
  "to": { "x": 110, "y": 60 }
}
```

新增：

```text
记录新增对象的完整数据
正着做：放进 Model
倒着做：从 Model 移除
```

删除：

```text
记录被删实例的完整数据
+ 被级联删除的边的完整数据
正着做：一起移除
倒着做：一起放回
```

不要逐字段猜「该记什么」；以本次操作实际影响的对象为边界。

## 5. 系统分层

```text
用户手势
  ↓
生成一条 transaction
  ↓
解释器正着/倒着执行
  ↓
Model 改变
  ↓
View 根据 Model 更新
```

职责：

```text
Model      只管现在是什么样
History    只管时间轴当前位置
Command    描述一次可逆变化
Interpreter 把 Command 翻译成 Model 操作
View       只管画出来
```

Model 不应该知道 History 存在。

## 6. 哪些变化应该进历史

进历史：

```text
新增、删除、移动、拉线、重连、改折点、批量修改
```

不进历史：

```text
鼠标悬停、当前选中、临时虚线、拖动预览、相机/视口变化
```

判断标准：

> 交互结束后，它是否改变了业务 Model？

改变就进历史；只是过程状态就不进。

## 7. 大系统不是只用一种方案

```text
频繁小操作       可逆命令 / 增量
一次复杂手势     transaction / batch
一次影响很多对象 局部快照
容灾恢复         周期完整快照
```

大型编辑器常用混合方案。Qt `QUndoStack`、X6 History 都是命令/事务思路；Redux 不可变状态适合 past/present/future 快照。

本项目保留「纯数据命令 + 解释器」，因为它更接近 Qt/X6 的工业编辑器方案。

## 8. 存档的心智模型

存档只保存当前 Model：

```json
{
  "version": 1,
  "design": {
    "definitions": [],
    "primitives": [],
    "pins": [],
    "snapOutline": []
  },
  "assembly": {
    "instances": [],
    "edges": []
  }
}
```

不存：

```text
当前选中了谁
鼠标悬停在哪
正在拖动的虚线
视口 x/y/zoom
临时预览
```

默认流程：

```text
保存文件 → 序列化当前 Model
加载文件 → 校验 version → 重建 Model → 清空 History → View 重画
```

历史命令本身是纯数据，理论上也能存；但默认产品不要求关掉页面后还能继续撤销，所以不保存历史。

## 10. 课程验收

能讲清下面五句话即可：

```text
1. 历史是一条可以前进后退的时间轴
2. 一次用户意图只产生一条记录
3. 记录必须足够正着做、倒着做
4. Model 管现在，History 管过程
5. 存档存现在，撤销存过程
```

最小实现已验证：一次拖动只产生一条命令；撤销、重做、快捷键、命令 JSON 往返均通过。
