# 第 13 章 · 引脚编辑

> 状态：13.1 – 13.6 已实现并浏览器验证；13.7 待做。
> 参照对象：AntV X6 PR `antvis/X6#5093`（`PortEditor` 插件，自有分支 `feat/port-editor-plugin`）。

## 为什么加这一章

第 1–8 课把"引脚"从头做了一遍，但做的是一条**教学形状**上的引脚：

```text
外形 = 人手写的一串曲线命令
轮廓 = 同一串命令再采样一次
```

它俩之所以严丝合缝，是因为写的是同一串字 —— 看起来"很准"，其实是自己跟自己对。
一旦真拿素材试，立刻现形（实测，把素材换成三角形、其他一行不动）：

```text
屏幕上：三角形        ✓ 素材换成功了
吸附轮廓：还是那条老曲线

点三角形底边中点 → 引脚落在老曲线上（离三角形 2.3px，纯属巧合）
点三角形右边中点 → 吸不到，加不出来
点空白处        → 引脚加成功了，落在离三角形 99px 远的地方
```

真实电力/工业元件库的素材是脏的：

```text
圆、六边形、齿轮（圆弧命令 A）、贝塞尔、多段拼合
用 <line> 画的线条简图
贴位图 / 贴外部 SVG / 贴内嵌 SVG 的
只有文字的
画一整块通铺底色的
有凹槽、内凹转角、挖洞的
被 display:none 藏起来的辅助几何
```

这一章回答一个问题：**素材千奇百怪，引脚往哪儿落、怎么编辑、怎么不被搞错。**

## 与 X6 PortEditor 的关系

X6 那版（PR #5093）已经证明了两件事，我们直接采用：

```text
· 不要去"找"轮廓，而是遍历素材里的每个几何图形，逐个问浏览器"你多长、走到 t 在哪"
· 坐标换算全交给浏览器（CTM），平移/缩放/旋转都不用特判
```

它没做透的，是我们这一章的主要增量：

```text
· 编辑动作只有"加"和"删"，没有拖动重定位，没有 hover 预览
· 引脚没有身份：没有编号、没有名字、没有输入/输出之分
· 隐藏件、图片、文字、use 一律读不了
```

它漏掉的一个真缺陷（实测确认，13.7 回填时修）：

```text
候选选择器 'rect,circle,ellipse,path,polygon,polyline' —— 漏了 line
实测：9 个图形里吸到 9 个，那条 <line> 不在候选里
后果：纯线条简图元件一个引脚都放不了（而工程简图最爱用 line）
```

## 13.1 轮廓从素材里读出来 ✅

- 素材挂进设计师 SVG 的一个 `<defs>` 里：不渲染、不占位、不挡点击，但几何 API 可用
- 挂载参数与 `<image preserveAspectRatio="xMidYMid meet">` 完全一致，换算由浏览器给出，零手写数学
- 遍历 `path/rect/circle/ellipse/polygon/polyline/line`，逐个取长度与采样点
- 采样间隔按周长自适应：`step = max(2, 长度 / 240)`
- 多图形"谁近算谁"；通铺底色被摘掉；读不了的如实报告原因
- 落点算法**故意没动**（仍复用 7.3），单图形下与 7.5 逐点一致，方便对照验收

## 13.2 引脚编辑闭环 ✅

```text
加   去掉 50px 硬阈值 → 改成"贴边 8 个单位以内，或者落在元件内部"
     悬停时先给虚线预览圈，点一下才真正生成
删   悬停引脚 → 变大变红 + 右上角冒出 ×，点 × 删除
拖   按住引脚沿轮廓滑动（落点仍然吸在轮廓上，拖不离）
尺寸 引脚半径、预览圈、删除徽标都按 1/zoom 反算，视觉大小与点击手感不随缩放漂移
```

绕开的一个坑：徽标画在引脚右上方 17 个单位、可点范围 ≈12.6 个单位，
而引脚命中半径是 12 —— 两个范围接不上，鼠标从引脚走向徽标的途中会先"离开引脚"，
徽标被收掉 → 永远点不着。修法是在 `pointermove` 里**先判徽标再判引脚**。

## 13.3 引脚语义与约束 ✅

引脚从"一个点"升级为"有身份的接点"：

```text
{ id, name, kind, x, y, u, v, normal, angle, direction, closed, shapeId }
        ▲     ▲                        ▲       ▲        ▲
        │     │                        │       │        └── 所在图形闭合与否
        │     │                        │       └── 离散档位（只给正交路由用）
        │     │                        └── 连续角度（朝向的真值）
        │     └── input / output / bidirectional
        └── P1、L_IN、TOP_OUT…
```

**修掉两个真缺陷：**

```text
① 外法线：从"猜"改成"推"
   7.3 靠"远离顶点平均质心"定正负 → 凹轮廓必错
   实测：凹槽内壁正确朝外是 (+1,0)，7.3 给的是 (-1,0)（引出线往元件肚子里走）
   13.3 改用绕向（鞋带和的两倍）：> 0 时 (dy,-dx) 就是朝外
   顺带得到更强的性质：轮廓反着绕，同一堵墙的朝外方向不变

② 开放折线：不再凭空多出一条边
   7.3 用 % 点数取模 → 给任何折线补一段"末点→首点"
   实测：点 (520,152) 会落在 (518.5,154.7) —— 那个位置素材里什么都没有
   13.3 用"首尾两点是否重合"判开闭（不看 Z 标记），开放图形只走真实存在的段
   并且诚实处理方向：开放图形 direction = null，angle 仍给出
```

**连接规则：**

```text
双向 = 通配；输入↔输出 = 可以；输入↔输入、输出↔输出 = 不行
同一个引脚接自己 = 不行；同一对引脚连两次 = 不行（正反都算同一条）
定义里找不到那个引脚 = 不行，并说清楚原因
```

规则是纯函数，装配交互只在**建边之前**插一道闸门，拒绝就只把理由交出来。

## 13.4 让「读不了的」也能被点 ✅

四类"浏览器没有几何 API"的东西，各有各的路：

```text
<image> 内嵌 SVG   → 解开 href 里那段 SVG，读里面的**真图形**（真外形）
<image> 位图       → 退成外接矩形（矩形近似，如实标注）
<text>             → 退成外接矩形（矩形近似）
<use> 引用符号      → 找到被引用的元素读它，自己补上 use 的 x/y（真外形）
被祖先藏起来的图形  → 几何本来就完好，收编即可（开关 includeHidden，默认关）
```

三个硬事实（实测）：

```text
① 被祖先藏起来的图形，长度与 getCTM 都完好 → 收编几乎免费
   但元素**自己** display:none 时 getCTM 会丢掉自身 transform（e=0 f=0）
   → 落点会静默偏移，只能如实报"读不了"
② <image> 的 href 里那段 SVG 文本拿得到（urlencoded 或 base64 都能解）
   外链的（https://…/a.svg）要异步取，本课如实跳过
③ <use> 本身无几何 API，但被引用的图形有；缺的是 use 的 x/y，自己补
```

第二层嵌套时浏览器帮不上忙，只能自己算 meet 换算 —— 所以它是本课唯一的"手写换算"，
抽成纯函数，并**拿 13.1 的实测值当基准**（浏览器给 4.2/14/0，手算必须给出同一组数）。

实测位置精确吻合：内嵌 SVG 的矩形解到 `x 63~183 y 43~218`，
与手算的 62.5/182.5/42.5/217.5 一致；`use` 的三角形解到 `x 580~719 y 130~267`。

## 13.5 坐标换算：有没有 getCTM，差多少 ✅ 已实现

前四步都在"轮廓从哪来"上做功。这一步退回来，把**那唯一一行换算**单独讲透。

```text
13.1  src/outline-source.js
      + applyCtm(ctm, point, ignoreTransform)   ← 导出：全仓库唯一用 getCTM 的地方
      + readShapes 新增 ignoreTransform 选项      ← 默认 false，13.1–13.4 行为一字不变
13.4  src/outline-resolve.js
      + 开关一路穿到"读几何"的两处（内嵌 SVG、use 目标）
        ↑ 不穿会出现**假对比**：位图/文字退外接矩形那套是手算 meet，本来就不走 getCTM
13.5  src/designer.js
      + 一个字段 ignoreTransform + collectShapes override（接缝只有一个）
```

一个开关、两块画布并排、四份素材。实测（画布都是 620×300）：

```text
素材                          左边（不换算）           右边（用 getCTM）        结论
① 尺寸 = 画布（对照）           x 40~545  y 45~235       x 40~545  y 45~235      完全相同
② 只有一半大（200×100）         x 5~189   y 7~90         x 26~576  y 22~269      左边缩在左上角
③ 带 transform 的分组           x 0~240   y 0~230        x 40~529  y 60~232      左边丢了平移+旋转
④ 内嵌 SVG 的图片               x 5~116   y 5~75         x 186~436 y 71~229      左边只有内层坐标
```

素材① 是最该看的一份：`viewBox` 与画布相同时矩阵是**单位矩阵**，两种模式等价 ——
这解释了为什么前 12 课那套在部分素材上一直是对的，也解释了 13.1 那句"与 7.5 逐点一致"
为什么成立（我挑的对照素材正好是这一类）。

素材② 与手算吻合：`scale = min(620/200, 300/100) = 3`、偏移 `(10,0)` →
`3×5+10 = 25 ≈ 26`、`3×189+10 = 577 ≈ 576`。

真实指针事件（素材②，左右画布**同一个画布坐标**各点一下）：左边**没有引脚落下**，
右边落在那条 path 上 —— 你点的是屏幕上看得见的曲线，而它不在左边认的那套坐标里。

## 13.6 遮挡判定：看不见的边不能点 ✅ 已实现

起因是 13.5 收工前发现并实测复现的一个真缺陷：**两个图形重叠时，下面那个露不出来的边照样吸引脚。**

```text
A  x 100~300          （下面那层）
B  x 250~450          （上面那层）
→ A 的右边缘整条落在 B 的填充里，屏幕上看不见
→ 点 (300,200)（屏幕这里是 B 的一片填充）引脚却精确落在 (300,200) 形状=A
→ 更糟：点 (350,200)（B 内部）引脚跑到 50px 外那条看不见的线上
```

判定规则只有一条，但它一句话说清三件事：

```text
图形 j 挡住图形 i 的点 P  ⟺  j 有实心填充、j 画在 i 后面、且 P 落在 j 的区域里（或边界上）
```

- 自己挡不住自己（顺序不可能大于自己）→ 凹图形不会被自己埋
- **只有画在上面的挡得住下面的** → 十字交叉的两块板，上面那块一条边都不丢
- 被埋是**点级**的 → A 只埋右边缘，上下左三条边照常可点

接缝只有一处：13.3 已经把放引脚/拖动/预览三处收口到 `model.snapAt`，13.6 覆盖它一个方法即全生效。
（顺带修掉一个既有不一致：13.2 的悬停预览原来直连 `placementHit`，用的是旧几何；
改成走 `model.snapAt` 后，预览和真正落点终于同一个判断。）

实测：素材「重叠外壳」被埋 91 / 482 点（A 91 点、B 0 点）；
真实指针事件下，被埋的边点不着了，而 A 的可见三条边照常能放。

**没引入布尔运算库**（见 README 的取舍说明）：并集能修这个缺陷，但会把看得见的内部边一起删掉，
还会丢掉每条轮廓的身份。

## 边界

- 不做"拖线即自动补端口"：端口必须是刻意为之的产物，否则图纸会凭空多出无名端子
- 不做位图的像素级边缘检测（画进 canvas 扫 alpha、边界追踪、抽稀）——
  成本高、跨域会污染 canvas、阴影/渐变会误判，属 13.4 明确列出的"第 3 档"
- 不做电压等级 / 极性 / 载流能力这类电气语义校验（那是产品层）
- 不做标注数据格式、不做产品级的元件库管理
- 每小课只加一条主线，前一课的 demo 冻结不覆盖
