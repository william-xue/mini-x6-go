# 第 8 章 · 元件定义、元件库、实例化

> 状态：进行中；当前为 8.6。

## 8.1 设计态生成元件定义

`toDefinition(model, name)` 把设计器状态编译成可独立保存的定义：

```js
{ id, name, size, background, snapPathData, snapOutline, primitives, pins }
```

- `pins` 只保存归一化 `u/v` 和 `direction`，不保存绝对坐标
- `primitives` 保留定义局部坐标，实例缩放时整组缩放

验收：

- [x] 生成的定义里引脚只有 `u/v/direction`
- [x] `u/v` 与画布尺寸无关
- [x] 背景、图元、轮廓资源都在定义里

## 8.2 定义 → 实例

`instantiate(definition, {x, y, scale})` 生成运行态实例；`<g>` 统一 `scale(scale)`，端口按 `u/v × 实例尺寸` 落位。

验收：

- [x] 一份定义能实例化成多个不同尺寸的实例
- [x] 实例端口按同一比例落位
- [x] 拖动实例时端口跟随
- [x] 每个实例端口是独立数据，互不影响

## 8.3 元件库与多实例

`Library` 按 id 保存定义，同 id 再保存为更新。`Workbench` 串联设计器 → 定义 → 库 → 装配画布，装配渲染复用 8.2 的 `Assembly`，不重复实现图元绘制。

验收：

- [x] 同 id 保存是更新而非新增
- [x] 同一份定义可反复实例化
- [x] 实例化后仍可拖动

## 8.4 装配画布端口连线

第 8 章的 `Assembly` 精简重写，本来没有边。8.4 补上：

```js
edge = {
  source: { instanceId, portId } | { x, y },
  target: { instanceId, portId } | { x, y },
}
```

- 边只保存端口引用，坐标由实例 x/y/width/height + 端口 u/v 现场解析
- 端口命中优先于实例拖动；拖拽显示虚线；松手吸附最近端口，空白则成悬空边
- 移动实例时相连边自动重算端点

验收：

- [x] 端口上按下是拉线，不是拖动实例
- [x] 松到另一个端口吸附成实线
- [x] 松到空白成悬空边
- [x] 移动实例时相连边跟随
- [x] 拖动结束后不残留虚线

## 8.5 定义裁切到元件外形

问题：`definition.size` 直接用设计画布，图形在画布里留白时，实例的包围盒 / 选中框 / 命中区都比元件大。

修法：`snapOutline` 的外接矩形作为元件外形框，定义阶段一次性裁切（`size`、`snapOutline`、`primitives`、`pins` 换到 body 坐标系，`background` 重写 viewBox）。

**踩坑（重要）**：第一次做这个修法时“没修好”。根因不在裁切，而在示例素材里画了一块与画布同尺寸的底色矩形：

```html
<rect width="420" height="240" fill="#fbfcff"/>
```

`viewBox` 只裁剪可见窗口，**不删除内容**，所以裁切后那块底色仍然铺满整个可见区域，看起来仍是一个比元件大的方框。删掉它之后 `image` 区域与实例包围盒实测完全重合（差值 0）。

结论：**素材规范 = 不画整画布底色矩形，viewBox 只包住图形本身。**

## 8.6 连线按端口方向前置引导

问题：8.4 的边是端点直连的 `<line>`，完全没用端口 `direction`，连两个同侧端口时直线会横穿元件本体。

修法：路由前先沿端口方向走出 18px 再折向对方（与 5.4 正交路由同思路），渲染从 `<line>` 换成 `<polyline>`。

验收：

- [x] 出线方向与端口 `direction` 一致
- [x] 进线从端口外侧进入
- [x] 每一段横平竖直
- [x] 悬空端退回直线
- [x] 选中提示沿真实轮廓高亮，不再显示外接矩形

**已知局限（未解决）**：同侧**同向**端口（如 A 右 → B 右）之间，走线仍会穿过元件本体。彻底避免需要障碍物避让，属第 10 课范围。

## 8.3 元件库

命名保存多个定义，一份定义可实例化多次；实例之间互相独立。
