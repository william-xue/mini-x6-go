# 第 13.5 课：坐标换算 —— 有没有 `getCTM`，差多少

## 一句话

同一份素材、同一段采样代码，**只有一个开关不同**：要不要用 `getCTM` 把点换算到画布坐标。

```js
src（13.1）新增的那个开关，就是全仓库唯一用到 getCTM 的地方：

export function applyCtm(ctm, point, ignoreTransform = false) {
  if (ignoreTransform || !ctm) return { x: point.x, y: point.y }   // ← 关：原样放行
  return {
    x: ctm.a * point.x + ctm.c * point.y + ctm.e,                    // ← 开：换算到画布
    y: ctm.b * point.x + ctm.d * point.y + ctm.f,
  }
}
```

左边关掉 = 假装没有 `getCTM` —— **这就是前 12 课的情形**，
只不过那时点的来源是人手写的 `pathData`，本来就写在画布坐标里，所以关掉也没事。

## 为什么这一课值得单独占一节

`getPointAtLength()` 返回的**永远**是"元素自己用户空间"里的点，跟屏幕上画在哪无关。
所以"读不读得出来"和"读出来的点在哪"是两件事：

```text
能把任意不规则形状量出一串点        ← getTotalLength + getPointAtLength（前 12 课就有）
把那些点放到画面上的正确位置        ← 靠 getCTM（这一课）
```

前 12 课的输入是自己按画布坐标写的曲线，两件事重合，看不出区别。
13.x 的输入是别人交给你的文件 —— 它有自己的 `viewBox`、自己的尺寸、自己的分组 `transform`，
两件事立刻分家。

## 实测对照（demo 里四份素材，全部真实运行）

画布都是 620×300。

```text
素材                          左边（不换算）           右边（用 getCTM）        结论
──────────────────────────────────────────────────────────────────────────────
① 尺寸 = 画布尺寸（对照）       x 40~545  y 45~235       x 40~545  y 45~235      两边完全相同
② 只有一半大（200×100）         x 5~189   y 7~90         x 26~576  y 22~269      左边缩在左上角
③ 带 transform 的分组           x 0~240   y 0~230        x 40~529  y 60~232      左边丢了平移+旋转
④ 内嵌 SVG 的图片               x 5~116   y 5~75         x 186~436 y 71~229      左边只有内层坐标
```

**① 是最该看的一份**：素材 `viewBox` 和画布一模一样时，浏览器给的矩阵是**单位矩阵**，
换算与不换算**等价**。这解释了为什么前 12 课那套方法在一部分素材上一直是对的 ——
也解释了我 13.1 那句"与 7.5 逐点一致"为什么成立：我挑的对照素材正好是这一类。

**② 手算能对上**：素材 200×100 铺进 620×300 → `scale = min(3.1, 3) = 3`，偏移 `(10, 0)`。
左边读到 `x 5~189`，右边 `3×5+10 = 25 ≈ 26`、`3×189+10 = 577 ≈ 576` ✓
（差 1 是采样点落在曲线上的取整，不是误差累积。）

**④ 两层坐标**：内层 SVG 是 120×80，放在 `(70,60) 480×180` 的图片位置 →
`scale = min(4, 2.25) = 2.25`，`offset = (70 + (480−270)/2, 60) = (175, 60)`。
左边读到 `x 5~116 y 5~75`（**就是内层 120×80 空间里的坐标**），
右边 `175 + 2.25×5 = 186.25 ≈ 186`、`175 + 2.25×116 = 436` ✓

## 真实指针事件：同一个位置点一下

素材②，在左右画布**同一个画布坐标**各点一下（真实 `pointerdown` / `pointerup`）：

```text
点 (300, 140)   左：没有引脚落下       右：引脚落在那条 path 上，朝 bottom
点 (120,  60)   左：引脚落下，但落点不同  右：引脚落在那条 path 上，朝 top
```

第一行是最直白的证据：**左边点了没反应** —— 因为左边那串"轮廓"离你点的位置一百多像素，
落点上限挡住了。你点的是屏幕上看得见的那条曲线，而它不在左边认的那套坐标里。

## 代码怎么来怎么去

```text
13.1/src/outline-source.js
    + applyCtm(ctm, point, ignoreTransform)    ← 导出，唯一用 getCTM 的地方
    + readShapes 新增 ignoreTransform 选项      ← 默认 false，13.1–13.4 行为一字不变
    + measureShape 多收一个参数往下传
    + index.js 导出 applyCtm

13.4/src/outline-resolve.js
    + ignoreTransform 一路穿到"读几何"的两处（内嵌 SVG、use 目标）
      ↑ 不穿的话会出现"某份素材两边一样"的**假对比**：位图和文字退外接矩形的那套
        是自己手算 meet，不走 getCTM，所以它本来就不受开关影响

    - Designer extends 13.4 的 Designer
    - 只加一个字段 ignoreTransform + collectShapes 的 override

```

**接缝只有一个**，所以"差多少"能被肉眼直接看见，而不是靠讲。

## 已知的边角（诚实记着）

1. **同一页跑两个设计器时，元素 id 会不同步**：`id` 用的是模块级自增计数器
   （`${tag}-${autoId++}`），所以左右两个画布会给同一份素材的同一个图形取到不同编号
   （demo 里左边 `path-19`、右边 `path-20`）。这不影响行为 —— 引脚引用的是**自己那个**
   设计器生成的 id —— 但意味着"同页多实例的 id 不通用"，将来若要做跨实例的持久化要注意。
   另外这样设计有个好处：重新读轮廓后旧 id 不会重复，旧引脚不会**静默绑到别的图形上**。
2. **三层以上嵌套 `<svg>` 没实测**：13.4 刻意把解析结果挂在"和素材同级"的位置，
   就是为了绕开多层 viewport 的语义。这条仍然是空白。
3. **裁剪 / 遮罩 / 粗描边不被遵从**：见 13.1 README 的「已知局限 0」。
   本课的四份素材都没用它们 —— 那不是坐标换算的事。
