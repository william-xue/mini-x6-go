# Lesson 13.1 · 轮廓从素材里读出来

## 要解决的问题

前 12 课里，"元件外形"和"吸附轮廓"是**两件互不相干的事**：

```js
const pathData = 'M240 80 C350 20 530 35 630 130 ...'   // 人手写的一串曲线命令
designer.setSvgBackground('component.svg', `<svg>...<path d="${pathData}"/></svg>`)  // 只负责显示
designer.setSnapPath(pathData, 6)                        // 只负责吸附
```

它俩之所以严丝合缝，是因为**写的是同一串字**。所以看起来"很准"，其实是自己跟自己对。

一旦真拿素材试，问题立刻现形（实测，把素材换成三角形、其他一行不动）：

```text
屏幕上：三角形            ✓ 素材换成功了
吸附轮廓：还是那条老曲线   ← 211 个点，跟三角形没关系

点三角形底边中点  → 引脚落在老曲线上（离三角形的边 2.3px，纯属巧合）
点三角形右边中点  → 吸不到，引脚加不出来
点三角形左边中点  → 吸不到，引脚加不出来
点空白处         → 引脚加成功了，落在离三角形 99px 远的地方
```

在真实图形上点加不出来，在空白处点反而加得出来。

## 心智模型

轮廓不该由人写，该由框架**问浏览器**。

浏览器把图形画了出来，所以它内部知道这条边的一切。我们只需要问它三句话：

```text
你这个图形一共多长？          el.getTotalLength()
从起点走 137 个单位落在哪？    el.getPointAtLength(137)
素材坐标 → 画布坐标怎么换？    el.getCTM()
```

第三句是关键。它不是"素材自己空间"到"屏幕"的一次乘法，而是**一串坐标系的接力**：
视口 → 画布 → 素材根 → 素材里的每个图形。浏览器一次全给你。

于是整个课只剩三步：

```text
1. 把素材挂进文档（否则浏览器不肯算，见下）
2. 遍历素材里的每个图形，逐个走一遍，得到一串点
3. 悬停时把点投影上去，谁离得近就算谁 —— 所以"各种形状都有"不是问题
```

## 两个实测出来的硬事实（别靠猜）

**一、没挂进文档的图形，浏览器不给长度**

```text
DOMParser 解析出来、从未挂进文档   → getTotalLength() 抛 InvalidStateError，getBBox() = 0x0
挂进文档（屏幕外 / visibility:hidden / display:none / <defs>）→ 正常
```

所以素材必须挂进文档。本课挂在设计师 SVG 的一个 `<defs>` 里，因为：

```text
不渲染         按 SVG 规范，defs 内容不直接绘制
不占位         getBoundingClientRect() = 0x0
不挡点击       document.elementFromPoint() 命中不到它
几何 API 全能  getTotalLength / getPointAtLength / getCTM 全部可用
```

**二、把换算交给浏览器，自己一行数学都不写**

挂进去的时候，用**和 `<image preserveAspectRatio="xMidYMid meet">` 完全一样**的定位参数：

```js
element.setAttribute('viewBox', 素材自己的 viewBox)
element.setAttribute('x', '0')
element.setAttribute('y', '0')
element.setAttribute('width', 画布宽)
element.setAttribute('height', 画布高)
element.setAttribute('preserveAspectRatio', 'xMidYMid meet')   // ← 与那张 <image> 同一个规则
```

实测对照（素材 viewBox `0 0 200 100`，画布 868×420）：

```text
手算 meet 规则         scale = 4.2   offset = (14, 0)
浏览器给的 getCTM  a=4.200 d=4.200 e=14.000 f=0.000
```

完全一致。所以屏幕上那张图和吸附用的轮廓**不可能对不上**——它们是同一个规则算出来的。

**三、"祖先藏起来"和"自己藏起来"不是一回事**

判"看不见"必须沿**祖先链**走，因为 `display` 不是继承属性：

```text
实测 getComputedStyle(...)
  被 display:none 的 <g> 包住的子元素   display = 'inline'    ← 不是 'none'！
  被 opacity:0  的 <g> 包住的子元素     opacity = '1'        ← 不是 '0'！
  被 visibility:hidden 包住的子元素     visibility = 'hidden' ← 只有它是继承的，能判对
```

后果（这一版最初就踩了）：素材里藏一层 `<g style="display:none">` 放辅助几何，
整组装饰会**全部变成引脚候选**。实测复现过 —— 本该 1 条候选，实际读到 3 条。

顺带一个礼物，它决定了后面能做到什么：

```text
被祖先藏起来的图形    长度 200 ✓   getCTM a=1 e=5 f=5 ✓   几何完整，只是不显示
元素自己被 display:none 长度 200 ✓   getCTM 退化成 e=0 f=0   ← 自身 transform 被丢掉
```

也就是说，**"让隐藏件也能被点"在技术上几乎是免费的**：只要不清掉它们，长度和坐标本来就都在。
（图片和文字不在此列 —— 它们根本没有几何 API，见 13.4。）

## 接口

```js
new Designer({ container, width, height, outline: {
  sampleCount: 240,          // 每条轮廓最多采多少个点
  ignoreBackground: true,    // 是否摘掉"通铺底色"
  outlineSelector: null,     // 手工指定哪条图形当主轮廓
}})

designer.setSvgBackground(name, svgText)   // 一换素材，轮廓自动跟着换
designer.readOutline()                     // 重读，返回诊断报告
designer.outlineReport                     // 最近一次诊断
designer.model.on('outline:read', report => ...)

// 想自己指定轮廓时，接口和 7.5 一样，仍然可用
designer.setSnapPath(pathData, step)
```

诊断报告 `report`：

```js
{
  ok, error, viewBox,
  shapes:  [{ id, tag, length, step, pointCount, primary }],  // 读到的候选轮廓
  backgrounds: [{ id, tag }],                                 // 被当成底色摘掉的
  skipped: [{ tag, reason, count }],                          // 读不了的和为什么
}
```

## 采样间隔为什么按周长分摊

固定步长两头都不对：大件太稀、小件太密。

```js
step = max(2, 长度 / sampleCount)
```

实测（演示素材）：

```text
通铺底色里的外壳   长度 1115.4   间隔  4.65
圆弧圆             长度  879.77  间隔  3.67     ← 正好 2π×140，几何吻合
凹槽外壳           长度 2600.0   间隔 10.83
斜线（很短）       长度  339.41  间隔  2        ← 撞到下限
```

## 已知局限（13.3 一起修）

0. **裁剪 / 遮罩 / 粗描边不被遵从（实测，2026-09-26 补记）**。
   读的是几何元素**自己声明的形状**，不是"它最终被显示成什么形状"：

```text
素材                             读到的东西                        与可见外形的关系
rect(60,60,700×300)              长度 2000   x 60~760 y 60~360    偏大
  + clip-path 裁成三角形                                            （裁剪没生效，读到裁剪前的矩形）
rect(100,380,200×20,stroke 40)   长度 440    x 100~300 y 380~400   偏内
  （描边 40，视觉 x80~320 y360~420）                                 （读到描边中轴线，差半个描边宽）
rect(500,60,300×120) + mask      长度 840    x 500~800 y 60~180    偏大
  （在 (700,200) r60 处挖洞）                                       （遮罩没生效）
circle r45（只有 fill，无 stroke） 长度 282.29 x 255~345 y 155~245  ✓ 正常
```

   为什么：`clipPath` / `mask` / `pattern` 的内容被**刻意**当成"模板"跳过（它们不是实体），
   副作用是"裁剪/遮罩的效果"也一并跳过了。粗描边则是几何本身的问题：
   描边是**画在中轴线两侧**的，几何里没有"外沿"这个概念。
   要修得做多边形布尔运算（求交/求差），成本高，不该在"零依赖"约束下硬写。

1. **落点算法本次故意没动**：仍然复用 7.3 的 `nearestPointOnOutline`，
   所以单图形素材下 13.1 的落点结果与 7.5 **逐点一致**（方便对照验收）。
2. **它把折线当闭合**：`nearestPointOnOutline` 按 `% 点数` 取模，等于给开放折线凭空补了一段
   **"末点 → 首点"**。画面上看不出来（虚线只是首→末连线），但落点判定会吸到那段不存在的线上。
   实测（「纯线条简图」素材，polyline 是 `400,90 → 470,210 → 620,210`）：

```text
点 (520,152) → 引脚落在 (518.5,154.7)，离点击处 3.0    ← 那个位置素材里什么都没有
点 (560,175) → 引脚落在 (559.0,176.8)，离点击处 2.0
点 (600,195) → 引脚落在 (598.3,198.2)，离点击处 3.6
```

   注意：对 `<line>` 这种只有一段的图形，补出来的正好是它自己那一段，所以看不出问题；
   多段 `polyline`、无 `Z` 的 `path` 才会露馅。
3. **它靠"远离质心"定外法线**，凹轮廓会算反。实测：

```text
凹槽外壳：把素材切成 x=340 的竖壁（材料在它左边）→ 正确朝外应为 (+1,0) = right
实测结果：落在 (340,270) 朝 left，法线 (-1,0)   ← 反了，引出线会往元件肚子里走
```

## 与前 12 课的差别，一句话

```text
前 12 课：人写一串曲线命令 → 机器按 6 像素采点 → 吸附
13.1：   机器问浏览器"这图形多长" → 自己走一遍 → 吸附
```

差的不是精度，是**这条线从谁手里来**。

## 验收

- [ ] 逐个点六种素材，虚线轮廓跟着变，并且贴在屏幕上那张图的边上
- [ ] 「规则外壳 + 通铺底色」：诊断里显示"摘掉底色 1 条"，候选只剩外壳
- [ ] 「圆 + 五边形」：读到 2 条，★ 标在圆上；点圆附近落在圆、点五边形附近落在五边形
- [ ] 「圆弧拼出的圆」：长度 ≈ 879.77（= 2π×140，说明圆弧真的被解开了）
- [ ] 「纯线条简图」：读到 3 条，**包含两条 line**；在 polyline 首末两端之间的空白处点一下，
      引脚会吸到一条不存在的对角线上（靶子留给 13.3）
- [ ] 「带凹槽的外壳」：点凹槽内壁，朝外方向是反的（这是给 13.3 留的靶子）
- [ ] 「带文字 / 图片 / 隐藏件」：只有左边那块矩形长出虚线轮廓；「断路器」是文字、右边花图是图片，
      都被列为"读不了"并给出原因；那条红色粗线用 `display:none` 藏着，被过滤掉，画面上看不到
- [ ] 「清除所有引脚」按钮：点一下画面上的引脚全清；**换素材时也会自动清**
      （否则旧引脚留在原地，新旧混在一起，看起来像"换了没反应"）
- [ ] 「带文字 / 图片 / 隐藏件」里那个 `display:none` 的组：诊断里 `rect` 与 `line` 都被列为
      「在 `<g>` 上 display:none，看不见」—— 这正是"只看元素自己会漏判"的写法
- [ ] 缩放/平移后，轮廓仍精确贴边（7.5 的视口坐标系没有被破坏）
