# 第 13.6 课：看不见的边不能点

## 一句话

给每条轮廓的每个采样点加一次判断：**它是不是被别的图形盖住了？**
盖住了就标 `buried`，落点时跳过这一段。

```js
// 13.6 的 model 只覆盖这一个口子
snapAt(point) {
  const snapped = nearestAcrossVisibleShapes(shapes, point, ∞)   // ← 只在"看得见的段"上找最近点
  ...
}
```

## 缺陷是什么（实测复现，不是想出来的）

素材里两个图形重叠时，**下面那个露不出来的边照样吸引脚**：

```text
A  x 100~300  y 100~300     （下面那层）
B  x 250~450  y 100~300     （上面那层，画在 A 上面）
→ A 的右边缘 x=300 整条落在 B 的填充里，屏幕上看不见
```

修之前（= 13.5 及以前的行为）：

```text
点 (300, 200)   ← 屏幕这里是 B 的一片填充，看不到任何边
   → 引脚落在 (300.0, 200.0)   形状=A   离点击处 0.0     ✗ 吸到隐形边上了

点 (350, 200)   ← 在 B 内部随便点一下
   → 引脚落在 (300.0, 200.0)   形状=A   离点击处 50.0    ✗ 点在 B 里，引脚跑到
                                                        50px 外一条看不见的线上
```

修之后：

```text
点 (300, 200)   → 落在 (250.0, 200.0)   形状=B   离点击处 50.0   ✓ 落到看得见的边
点 (350, 200)   → 落在 (350.0, 100.0)   形状=B   离点击处 100.0  ✓
```

## 判定规则：一条就够

```text
图形 j 挡住图形 i 的点 P  ⟺  j 有实心填充、j 画在 i 后面、且 P 落在 j 的区域里（或边界上）
```

**这一条规则同时解决了三件事**，所以不需要额外的特判：

```text
① 自己不会挡住自己    顺序不可能大于自己 → 凹图形不会被自己埋掉
② 只有上面那个挡得住   两个重叠图形里，下面那个挡不住上面那个
③ 被埋是"点级"的       一条轮廓上常常只有一部分被盖（A 只剩右边缘被埋，上下左三条边都在）
```

② 为什么要紧：如果按纯几何来（谁的区域盖住谁就算），**画在上面那个的可见边会被误判成被埋** ——
十字交叉的两块板里，横板压着竖板，横板自己的边一条都不该丢。

## 为什么"有实心填充"才算遮挡

```text
fill: none        → 不算   描边轮廓挡不住任何东西，否则外面套个大方框就把里面全埋了
fill-opacity: 0.4 → 不算   半透明看得见（用户 2026-09-26 定的：看得见就不该算盖住）
opacity: 0.4      → 不算   同上
没写 fill         → 算     SVG 里没写 fill = 实心黑，它确实挡得住
rgba(0,0,0,0)     → 不算   alpha 为 0
```

"没写 fill 算实心"这条容易踩：`fill` 是**继承**属性，所以必须读 `getComputedStyle` 的计算值，
不能看元素自己有没有这个属性。

## 边界容差：实测发现的一个真问题

射线法**对"点正落在边界上"没有答案**。实测两个完全重合的矩形：

```text
下面那个的 21 个采样点里，只有 10 个被射线法判成"在里面"
→ 画面上会出现"一半灰一半紫"的花斑，而且每次重读结果可能还不一样
```

所以判定分两步：

```js
点被盖住 ⟺ 点在遮挡者区域**里面**（射线法）
          或者 点到遮挡者边界**距离 ≤ 0.75**（BOUNDARY_EPSILON）
```

共边（两个矩形贴在一起）同理。加上容差之后，重合与共边的情况结果**是确定的**。

## 已知局限（诚实记着）

1. **位图 / 文字 / `use` / 内嵌 SVG 解出来的轮廓不参与遮挡判定**。
   它们的"区域"我们本来就只有近似（外接矩形或解开后的图形），拿它们当遮挡者会误埋。
   所以：一张不透明位图盖住一条边时，那条边**仍然**会被吸引脚。属于已知缺口。
2. **`fill-rule="evenodd"` 的孔洞没处理**。射线法按普通环绕规则判，带孔洞的图形会把
   "孔里的点"也判成在里面。工业素材里少见，但存在。
3. **半透明一律不算遮挡**（用户定的规则）。所以 60% 透明度的遮罩底下那条边还是能点。
4. **性能没测大规模**：目前是"每个点 × 每个遮挡者"的两两判定，靠外接矩形粗筛。
   6–7 个图形无感；几百个图形的图纸需要空间索引。

## 这一课没做什么

- 没引入 Paper.js 或任何布尔运算库（仓库硬约束是零运行时依赖）。
  布尔并集能修这个缺陷，但它会把**看得见的内部边一起删掉**（比如壳里一个可见的圆环），
  还丢掉每条轮廓的身份（`pin.shapeId` 无从归属）。这一课要的是手术刀，不是大锤。
- 没碰 13.7（把这套成果回填成 AntV X6 插件）。
