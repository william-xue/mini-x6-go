## 待办清单（本文件的主体）

### 1. 引脚不进撤销栈

13.2 的「删除引脚」「拖动引脚」目前撤不回来，依赖第 9 课的 9.2（命令栈现在只覆盖"移动实例"）。

- 现状：`model` 侧的 `pin:added` / `pin:removed` / `pin:changed` / `pin:moved` 事件**已就位**
- 接法：将来接命令栈只需在这些事件上挂一对 `apply` / `revert`
- 归属：第 9 课 9.2（不是第 13 章）

### 2. 路由仍只认 4 向

引脚朝向的**真值**是连续的 `angle`；`direction` 只是给正交路由用的离散档位（`cardinal4`）。

- 现状：引脚 stem 已沿 `angle` 画，所以斜边上视觉是斜的
- 缺口：正交走线仍横平竖直，斜边引脚不会沿斜向引出
- 接法：路由层改读 `angle` 即可，本课不动它
- 归属：第 5.4 / 第 8.6 课的路由层

### 3. 位图不做像素描边（已排除方案，不是待办）

`<image>` 位图目前在 13.4 里只退成**外接矩形**。像素级边缘检测被明确排除：

```text
做法：画进 canvas → 扫 alpha 通道找不透明边界 → 边界追踪 → 抽稀
排除理由：跨域图片会污染 canvas；锯齿噪声大；点数暴增必须抽稀；
          带阴影/渐变的位图会把"描边"误判成边界
```

如果将来甲方坚持要"贴着位图里的真实外形放引脚"，再翻出来评估 —— 它是 13.4 文档里列的"第 3 档"。

### 4. 裁剪 / 遮罩 / 粗描边不被遵从（实测，2026-09-26 补记）

读轮廓读的是几何元素**自己声明的形状**，不是"最终被显示成什么形状"。实测：

```text
rect 被 clip-path 裁成三角形    → 读到裁剪前的整个矩形（偏大）
rect 被 mask 挖了个洞            → 读到完整的矩形（偏大）
粗描边（stroke-width 40）        → 读到描边中轴线，不是外沿（偏内半个描边宽）
只有 fill 没有 stroke 的实心块    → ✓ 正常
```

**这条对"任意真实素材"是实打实的风险**：Illustrator / CorelDRAW 这类工具导出 SVG 时
很爱加 clip-path，画布级的裁切很常见。如果裁切框正好大于内容，没问题；
但一旦裁切真的切掉了形状，读到的轮廓就会偏。

要修得做多边形布尔运算（求交/求差）—— 能做，但不便宜（robust 的裁剪库要几百行 + 一堆退化情况），
不该在"零依赖"约束下硬写。**目前状态：知道、记着、没做。**

### 5. 大规模素材的性能没测

`pointermove` 时对**所有**轮廓的**所有**段做全量最近点扫描（`nearestPointOnAnyShape`），
没有任何空间索引（网格 / 四叉树 / BVH）。

- 已测规模：6–7 条轮廓 × 每条约 240 点 → 完全无感
- 未测规模：几百个图形的复杂图纸，每次移动鼠标就扫一遍 → **大概率会卡**
- 补充方式：给轮廓做一层格子索引，或把"候选裁剪"提前到按 bbox 粗筛

### 7. 遮挡判定的两个缺口（13.6 已知，未做）

```text
① 位图 / 文字 / use / 内嵌 SVG 解出来的轮廓**不参与**遮挡判定
   理由：它们的"区域"本来就只有近似（外接矩形 / 解开后的图形），
         拿来当遮挡者会误埋（文字的外接矩形往往远大于字形）。
   后果：一张不透明位图盖住一条边时，那条边**仍然**会吸引脚。

② fill-rule="evenodd" 的孔洞没处理
   射线法按普通环绕规则判，带孔洞的图形会把"孔里的点"也判成在里面。
   工业素材里少见，但存在。

③ 半透明一律不算遮挡（用户 2026-09-26 定的规则）——
   所以 60% 透明度的遮罩底下那条边还是能点。这是**有意的**，不是缺陷。
```
